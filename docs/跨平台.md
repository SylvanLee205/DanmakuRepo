# 跨平台现状：Linux / macOS 能不能用？

**结论：核心功能能跑，但不能"开箱即用"，而且我们没有在真实 Linux 上验证过。**

写这份文档是因为被问到了，而且答案并不简单 —— 不想用"理论上可以"糊弄过去。

---

## 一、依赖层面：没有障碍

这是最容易卡住的地方，好消息是它不卡：

| 依赖 | Linux | macOS | 说明 |
|---|---|---|---|
| `stream-gears` | ✅ manylinux | ✅ x86_64 + arm64 | biliup 的 Rust 录制引擎，官方有预编译包 |
| `dmconvert` | ✅ | ✅ | 纯 Python（`py3-none-any`） |
| ffmpeg / ffprobe | ✅ | ✅ | 包管理器 / 官方静态构建 |
| rclone | ✅ | ✅ | 同上 |
| `DMR/` 包本身 | ✅ | ✅ | 只有 `toolsmgr.py` / `instance_lock.py` 两处判断平台，都有非 Windows 分支 |

`python -c "import stream_gears"` 在 Linux 上应该能过。

## 二、启动层：全是 Windows 的

这是真正的障碍。项目是围绕 Windows 无人值守部署长出来的：

| 功能 | 实现 | Linux 上 |
|---|---|---|
| 启动 | `Start_DMR.bat` + `_env.bat` | ❌ 批处理，不能跑 |
| 崩溃重启 | bat 里的 `goto loop` | ❌ 应该交给 systemd |
| 三层自启 | 计划任务（`schtasks`）+ Startup 目录 | ❌ 要换成 systemd unit |
| 跨会话迁移 | `DMR_SessionWatch` | ❌ 概念本身是 Windows 的（session 0/console） |
| 桌面快捷方式 | `WScript.Shell` COM 建 `.lnk` | ❌ 要换成 `.desktop` 文件 |
| 工具定位 | 读注册表 PATH | ⚠️ 已有非 Windows 分支，只查 PATH |
| 上传目标 | CloudDrive2 挂成盘符 | ⚠️ CD2 有 Linux 版，但走 FUSE，路径写法不同 |

## 三、已经做了的跨平台兼容

2026-11-02 补的（都是为了"至少别在明显的地方炸"）：

- `DMR/paths.py`：`system32()` 在 POSIX 上直接返回裸名字；`powershell_exe()` 返回 `pwsh`
- `DMR/notify.py`：curl 在 POSIX 上叫 `curl`（不带 `.exe`）
- `tools/build_index.py`：`--open` 用 `xdg-open` / `open`
- `tools/bootstrap.py`：非 Windows 跳过桌面快捷方式和计划任务
- `DMR/utils/toolsmgr.py`：`install_tool()` 在非 Windows 上只给包管理器指引，不下载 Windows 二进制
- 新增 `setup.sh` / `start.sh` / `stop.sh`

## 四、现在能在 Linux 上做什么

```
./setup.sh      # 建 venv、装依赖（会跳过所有 Windows 专属步骤）
./start.sh      # 前台启动录制
./stop.sh       # 优雅停止
```

**能录、能渲染、能上传**（只要 ffmpeg / rclone / 中文字体装好）。

`start.sh` 会检查系统有没有 CJK 字体 —— 这一点很关键：
libass 找不到字形会输出坏帧，`imgutils.c:351` 断言直接让整场渲染失败
（Windows 上踩过一次，见 `docs/排查记录-20261102-渲染崩溃三个真凶.md`）。

## 五、还差什么（按建议顺序）

1. **systemd unit**（半天）
   ```
   [Unit]
   Description=DanmakuRepo
   After=network-online.target
   [Service]
   WorkingDirectory=/opt/DanmakuRepo
   ExecStart=/opt/DanmakuRepo/.venv/bin/python main.py --quiet
   Restart=always
   RestartSec=10
   [Install]
   WantedBy=multi-user.target
   ```
   有了它就不需要 bat 的守护循环，也不需要三层自启（Linux 没有 session 0 那套问题）。

2. **实测一遍**（1 天）
   在一台干净的 Debian 上跑通"装 → 录 1 小时 → 渲染 → 上传"。
   目前所有 Linux 相关代码都是**照着接口写的，没有真跑过**。

3. **CD2 / 上传目标**（1-2 天）
   现在上传目标是 `cd2:百度网盘/...`（rclone remote 指向 CD2 挂载）。
   Linux 上要么装 CD2 的 FUSE 版，要么直接给 rclone 配 WebDAV remote 绕开 CD2。

4. **`.desktop` 快捷方式**（2 小时）
   照 `install_desktop_links.py` 的结构写一个生成器即可。

5. **健康检查脚本**（2 小时）
   `Doctor.bat` 里的 schtasks 检查要换成 `systemctl status`。

**合计约 3-5 天**，前提是有一个真实的 Linux 环境可以反复试。

## 六、macOS 的特殊问题

- `stream-gears` 有 arm64 轮子，但**没人验证过**在 Apple Silicon 上的录制稳定性
- 没有 CD2 官方 macOS 版（需换 rclone 直连）
- libass 中文字体一般没问题（系统自带苹方）
- launchd 替代 systemd，概念类似但有坑

建议：**macOS 优先级放最低**。目标是"能跑"而不是"无人值守"的话，倒是可以很快。

## 七、如果只是想在 Linux 上临时用一下

不需要上面那些。手动执行就够：

```bash
sudo apt install ffmpeg fonts-noto-cjk
curl -O https://downloads.rclone.org/rclone-current-linux-amd64.zip && unzip -j '*.zip' rclone -d tools/

./setup.sh
.venv/bin/python tools/add_room.py      # 按提示粘贴直播间链接
./start.sh
```

录出来的源视频在 `直播回放/原视频/<主播>/`（含 .ass 弹幕，上传后按 24h 延迟队列删），
渲染成品在 `直播回放/弹幕版/<主播>/`（**永久留本地**，命中跳过上传规则的分段也留，只是不传云）。
成品文件名必须带 `（弹幕版）` 后缀 —— Cleaner 靠它判断永不删除。
上传需要自己配 rclone remote（`rclone config`），然后把 `configs/global.yml`
里 `upload_args` 的 remote 改成你配的名字。
